Для начала – попробуйте загрузиться вручную из grub rescue

В режиме ``rescue`` доступен только ограниченный набор команд: ``ls, set, insmod, linux, initrd, boot``.

#### Шаг 1. Посмотрите доступные диски и разделы
Введите:
```text
ls
```
Вы увидите что-то вроде (hd0) (hd0,msdos1) (hd0,msdos2) или (hd0,gpt1) (hd0,gpt2).

#### Шаг 2. Найдите раздел с файлами /boot/grub
По очереди пробуйте:
```text
ls (hd0,1)/
ls (hd0,2)/
ls (hd0,msdos1)/
```
Если видите папки grub или boot, то это ваш системный раздел (или загрузочный). Допустим, это (hd0,msdos1).

#### Шаг 3. Укажите GRUB правильные параметры
```text
set prefix=(hd0,msdos1)/boot/grub
set root=(hd0,msdos1)
insmod normal
normal
```
> - Если insmod normal не работает (ошибка unknown filesystem), попробуйте сначала загрузить модуль для файловой системы, например:

```text
insmod ext2
```
(если у вас ext4 – подойдёт ext2).

После normal вы должны попасть в обычное меню GRUB. Если нет – переходите к следующему шагу.

#### Шаг 4. Загрузите Linux напрямую (если normal не запускается)
Найдите ядро и initrd:
```text
ls (hd0,msdos1)/boot/
```
Ищите файлы, похожие на ``vmlinuz-...`` и ``initrd.img-....`` Затем введите:
```text
linux (hd0,msdos1)/boot/vmlinuz-5.15.0-100-generic root=/dev/sda1 ro
initrd (hd0,msdos1)/boot/initrd.img-5.15.0-100-generic
boot
```
> - (Замените пути и версию ядра на свои, а sda1 – на соответствующий раздел, например hd0,msdos1 – это может быть /dev/sda1).

####  Если ничего не помогло – загрузитесь с Live USB и восстановите GRUB
Режим unknown filesystem часто означает, что GRUB не узнаёт файловую систему раздела (например, из-за сбоя, изменения разделов или повреждения суперблока).

Что делать:

Загрузитесь с установочной флешки Linux (в режиме «Live», «Попробовать без установки»).

Откройте терминал.

Узнайте, какой раздел является корневым:
```text
sudo fdisk -l
sudo blkid
```
Найдите раздел с типом ext4 или btrfs, обычно это /dev/sda2, /dev/sda3 и т.д.

Примонтируйте его (например, /dev/sda2):
```text
sudo mount /dev/sda2 /mnt
```
Если /boot на отдельном разделе – примонтируйте и его.

Переустановите GRUB:

Для BIOS/legacy:
```text
sudo grub-install --root-directory=/mnt /dev/sda
```
Для UEFI:
```text
sudo mount /dev/sda1 /mnt/boot/efi   # обычно EFI раздел
sudo grub-install --target=x86_64-efi --efi-directory=/mnt/boot/efi --boot-directory=/mnt/boot
```
Обновите конфигурацию:
```text
sudo update-grub --output=/mnt/boot/grub/grub.cfg
```
Перезагрузитесь, сняв флешку.

#### Для полного выхода из GRUB (если он не нужен)
Если вы хотите не чинить GRUB, а переключиться на другой загрузчик (например, Windows Boot Manager), то после загрузки с Live USB можно просто удалить GRUB с диска:

Для UEFI: удалить папку ```/boot/efi/EFI/ubuntu (или где у вас GRUB)`` и через ``efibootmgr`` изменить порядок загрузки.

Для BIOS: перезаписать MBR командой sudo ``dd if=/dev/zero of=/dev/sda bs=446 count=1`` (осторожно! Это удалит загрузчик полностью).

Но проще всего – войти в ``BIOS/UEFI (клавишами F2/Del при старте)`` и поставить в загрузке первым ``Windows Boot Manager``, если система двойная.

> - Главный вывод: из grub rescue нет команды, которая просто вернёт вас в меню. Нужно либо вручную загрузиться (команды выше), либо восстановить загрузчик с Live USB. 

#### GRUB в режиме rescue
Если на команды 
```text
ls (hd0,1)/
ls (hd0,2)/
ls (lvm/pve-root)/
```
не реагирует и пишет error: disk 'lvm/pve-root' или не верная файловая система, то

GRUB в режиме rescue всё равно «теряет» этот LVM-том при попытке прочитать с него данные (выдаёт error: disk 'lvm/pve-root' not found на команду insmod). Мучить консоль rescue дальше нет смысла, она слишком ограничена.

Загружаемся с установочного **Live CD / USB** в режим восстановления, зайти в chroot и сделать правильную установку с принудительным созданием нового образа загрузчика.

Выполняем команды:

##### Шаг 1. Автоматическое монтирование системы
В консоли введите команду:
```bash
mount-system
```
Этот фирменный скрипт Альт Линукс сам найдет установленную ОС, смонтирует корневой раздел, а также все необходимые виртуальные каталоги (/dev, /proc, /sys)<br>
Если скрипт отработает успешно, вы автоматически окажетесь внутри вашей установленной системы (в окружении chroot).

Если скрипт mount-system выдал ошибку, выполните монтирование вручную:
```bash
mount /dev/sdXY /mnt     # Где sdXY — ваш корневой раздел (например, sda2)
mount --bind /dev /mnt/dev
mount --bind /proc /mnt/proc
mount --bind /sys /mnt/sys
chroot /mnt
```
##### Шаг 2. Перейдите в окружение вашей системы (chroot)
Выполните команду, чтобы переключить консоль на смонтированную систему:
```bash
chroot /mnt/system1
```
После этого внешний вид приглашения строки (в начале строки вместо ``[root@localhost ~]#``) может измениться.

##### Шаг 3. Пересборка initramfs (образа загрузки)
Проблема в том, что ядро не понимает текущую конфигурацию LVM. 

Пересоберем загрузочный образ внутри Альт Линукс:
```bash
make-initrd
```
Дождитесь завершения процесса (команда может занять около минуты)

##### Шаг 4. Принудительное обновление конфигурации GRUB
```bash
update-grub
```
##### Шаг 5. Финальная установка загрузчика
Так как диск в разметке GPT, а загрузка идет в режиме ``Legacy``, убедимся, что GRUB встанет чисто:
```bash
grub-install --target=i386-pc --recheck /dev/sda
```
После этого пишите ``exit``, затем ``reboot``, вытаскивайте флешку и проверяйте старт.

#### Не возможно ничего сделать в режиме rescue
Поскольку на диске sda вообще нет EFI-раздела (обычно он имеет размер от 100MB до 512MB и файловую систему FAT32), ваша система гарантированно должна загружаться в режиме Legacy (BIOS), а не UEFI.

Причина, по которой GRUB падал в grub rescue, заключается в том, что при установке i386-pc он не смог корректно прописать путь к корневому разделу LVM внутри метаданных GPT. 

Чтобы решить эту проблему в режиме Legacy, нужно применить альтернативный метод активации LVM при установке загрузчика.

<img width="722" height="398" alt="image" src="https://github.com/user-attachments/assets/1ed87801-1ae7-48c5-a088-fc8633821721" />

Выполните в консоли восстановления следующие команды:

##### Шаг 1. Проверьте активацию LVM томов

Убедитесь, что Live-система видит и активировала ваши тома (особенно pve-root), выполнив команду:
```bash
vgchange -ay
```
(Должно появиться сообщение, что тома активированы)

##### Шаг 2. Зайдите в окружение chroot
В консоли введите команду:
```bash
mount-system
```
Если вы выходили из него, вернитесь обратно:
```bash
chroot /mnt/system1
```
(Если папка не смонтирована, предварительно запустите mount-system)

##### Шаг 3. Установка GRUB с созданием блочного листа (Blocklist)
Так как у вас GPT-разметка без EFI-раздела, стандартная установка на sda может сбоить. 

Мы заставим GRUB принудительно использовать раздел sda1 (BIOS boot) для хранения своего образа, проигнорировав возможные предупреждения:
```bash
grub-install --target=i386-pc --force /dev/sda
```
##### Шаг 4. Принудительное включение LVM в конфиг GRUB
Чтобы GRUB не терял диск ``lvm/pve-root`` при старте, нужно явно сказать ему сгенерировать конфигурацию с поддержкой LVM. Введите:
```bash
grub-mkconfig -o /boot/grub/grub.cfg
```
Внимательно посмотрите на вывод команды: в списке найденных модулей или генерируемых строк обязательно должен упоминаться LVM или pve-root

##### Шаг 5. Выход и проверка
```bash
exit
reboot
```
